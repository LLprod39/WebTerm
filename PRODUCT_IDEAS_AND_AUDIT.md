# Отчет по аудиту и развитию продукта WebTerm (AI Platform)

## 1. Введение
Данный документ содержит анализ текущего состояния проекта WebTerm, а также стратегические предложения по его развитию. Анализ разделен на две основные категории: **"Что убрать"** (избыточный код, бесполезные фичи, технический долг) и **"Что добавить"** (архитектурные улучшения, новые востребованные функции для целевой аудитории - Ops/DevOps инженеров).

---

## 2. Что убрать (Избыточные и бесполезные функции)

После анализа кодовой базы и документации были выявлены следующие компоненты, которые усложняют поддержку проекта и не приносят соразмерной пользы:

### 2.1. Десктопный клиент (WinUI 3 - `desktop/`)
**Почему это избыточно:**
- Весь основной функционал приложения реализован как SPA (React/Vite) с доступом через браузер. Современные веб-браузеры отлично справляются с рендерингом терминалов (`xterm.js`) и WebSocket соединениями.
- Поддержка отдельного толстого клиента на C# (WinUI) под Windows требует огромных ресурсов, дублирования API и логики.
- Для десктопного опыта лучше превратить React-приложение в PWA (Progressive Web App) или обернуть в легкий Tauri/Electron, если действительно нужен доступ к локальной ОС (хотя концепция платформы подразумевает управление удаленными серверами).
**Рекомендация:** Заморозить или полностью удалить директорию `desktop/`.

### 2.2. Забытые и отключенные модули
- **Модуль `passwords/`:** В корне проекта находится директория `passwords/`, которая, согласно `README.md` и `settings.py`, исключена из `INSTALLED_APPS`. Это мертвый код, который только путает разработчиков.
**Рекомендация:** Удалить директорию `passwords/`.

### 2.3. Архитектурный мусор и нарушение границ (Bounded Context)
Как было отмечено в `PROJECT_AUDIT.md`:
- **`servers/mcp_tool_runtime.py`:** Выступает в роли устаревшего shim (перехватчика), который перенаправляет логику в `studio`. Это нарушает границы Bounded Context.
**Рекомендация:** Удалить файл из `servers/` и полностью перенести ответственность в `studio`.

## 3. Что добавить (Чего не хватает платформе)

Проект выглядит как мощный комбайн для Ops-инженеров, но для полноценного покрытия DevOps-сценариев ему не хватает нескольких ключевых интеграций и архитектурных улучшений.

### 3.1. Интеграция с Kubernetes (K8s)
**Проблема:** В данный момент платформа отлично работает с "голым железом" (SSH/RDP, Ansible) и Docker-контейнерами (Linux UI). Однако де-факто стандартом оркестрации является Kubernetes.
**Что добавить:**
- Реализовать `K8sAgent` и панель управления подами/логами в `Linux UI`.
- Внедрить возможность для Nova AI использовать команду `kubectl` в песочнице с правильным парсингом манифестов.

### 3.2. Нативная интеграция с CI/CD и Git
**Проблема:** Инженеры редко просто правят файлы на сервере (только при инцидентах). В основном они пишут Infrastructure as Code (IaC) в Git.
**Что добавить:**
- Добавить возможность для агентов создавать Merge/Pull Requests в GitHub/GitLab вместо прямой записи файлов через `files.write`.
- Внедрить визуализацию пайплайнов GitLab CI / GitHub Actions прямо в `Studio`.

### 3.3. Улучшение безопасности (Security Hardening)
Опираясь на отчет об аудите, необходимо внедрить следующие изменения:
- **Безопасность команд (Shell Injections):** Заменить базовую проверку на Regex в `app/tools/safety.py` на парсинг Abstract Syntax Tree (AST) с использованием библиотеки типа `bashlex`. Это предотвратит обход фильтров через обфускацию команд.
- **Шифрование паролей:** Перевести `PasswordEncryption` с PBKDF2HMAC (100,000 итераций) на Argon2id или, как минимум, увеличить количество итераций до 600,000.
- **Детекция секретов:** Улучшить `app/agent_kernel/memory/redaction.py`, добавив проверку на высокую энтропию строк (Shannon Entropy), а не только поиск по ключам `password|token`.

### 3.4. Архитектурный рефакторинг (Технический долг)
- **Устранение N+1 запросов:** Внедрить пагинацию и использование `.prefetch_related()` и `.select_related()` на всех View, особенно в модулях `servers` и `core_ui`.
- **Разделение Sync/Async:** Вынести тяжелые синхронные операции (например, `ast.literal_eval` при парсинге большой AI-памяти в `store.py`) в `sync_to_async`, чтобы не блокировать Event Loop Django Channels.
- **Изоляция инструментов:** Вынести инструменты, жестко завязанные на ORM (`servers_tools.py`, `ssh_tools.py`), из общего `app/tools` в домен `servers/tools/`.

### 3.5. Инструментарий мониторинга (А-ля Grafana)
**Проблема:** Сейчас метрики (CPU/RAM/Disk) показываются в UI, но нет возможности строить исторические графики по кастомным метрикам.
**Что добавить:**
- Добавить встроенную визуализацию временных рядов (Time-Series) для анализа памяти L0/L1/L2. Это позволит Nova не только читать логи, но и строить графики изменения метрик перед инцидентом.

---

## Итог
Платформа имеет огромный потенциал как "Умный терминал". Чтобы стать лидером в своем классе, ей стоит отказаться от поддержки десктопа (WinUI) в пользу веб-технологий, устранить утечки архитектурных границ и сфокусироваться на современной экосистеме (Kubernetes, CI/CD) и безопасности.
