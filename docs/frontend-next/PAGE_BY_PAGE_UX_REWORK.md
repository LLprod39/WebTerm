## Подробные проходы

Сюда добавляется фактический разбор страницы после повторной браузерной проверки, включая сохранённые функции, удалённые дубли, Advanced, каждый control group и границы внешних действий.

### 01 — Вход

Браузер до/после: brand → /login, оба поля, native required validation, показ/скрытие пароля, раскрытие/сворачивание дополнительных параметров, local checkbox, Enter/submit, неверные данные, исправление и успешный вход. Единственная основная задача — войти в пространство. Local auth перенесена в «Дополнительные параметры входа» с пояснением; удалены декоративная псевдосхема CONNECT/OBSERVE/AUTOMATE и повторные лозунги. Заголовок основной формы теперь H1. Ошибка неверного пароля больше не называется завершённой сессией. Во время запроса поля и отправка заблокированы, текст кнопки меняется на «Входим…».

Состояния: пустая форма, invalid credentials, pending/disabled, 503 с сохранёнными данными, recovery/success проверены в `ux-login.spec.ts` (PASS 1/1, реальный backend + test-only задержка/503). Mobile 390×844 и axe — PASS; screenshot `frontend/artifacts/ux/01-login-mobile.png`. API regression 9/9. Tabs/context menu/select/modal/pagination здесь отсутствуют и не добавляются. Внешний LDAP login не выполнялся.

### 02 — Обзор и навигация

Ручной браузерный проход: обзор, все четыре показателя и три полезные секции; поиск по серверу и очистка пустого результата; сортировки «Сервер», CPU, «Память»; обновление; темы; меню аккаунта; выход и повторный вход. Основное действие «Добавить сервер» открывает форму сразу, отмена возвращает в список; проверены целевые переходы к мониторингу и аудиту с возвратом на обзор. Палитра ищет существующий QA-сервер и закрывается явной кнопкой.

Изменения: удалён блок «Рабочие инструменты», повторявший навигацию и обещавший запустить действие, хотя открывал каталог. Из персональной схемы удалён только этот блок, остальные и сторонние JSON-настройки сохраняются. В короткой таблице обзора скрыты неработающие стрелки единственной страницы; при нескольких страницах пагинация остаётся. Ошибка/загрузка/нет прав отделены от настоящего пустого списка; при неудачном обновлении полученных ранее данных показано предупреждение. Последние операции отделены от шумных login/logout/http-записей, указана личная область истории. Оповещения ведут к мониторингу; аудит доступен соответствующей роли.

Shell: убраны повторный brand/footer и desktop hamburger, уточнены названия поиска и настроек, добавлено закрытие поиска и честные loading/error/retry состояния серверного поиска. Offline-текст не обещает автоматического сохранения или отправки. Итоги повторной проверки мобильной клавиатурной навигации и состояний приведены ниже.

QA-предусловия этого прохода: помимо PostgreSQL изолированы MODEL_CONFIG_PATH, OLLAMA_CACHE_PATH, uploads/SSH keys/skills/bundles, временные файлы, logs и package retention; рабочие AI/LDAP/runner endpoints и ключи не наследуются. Для Ollama добавлен явный путь cache-marker с сохранением прежнего поведения по умолчанию (pure unit 2/2). После перезапуска QA9001 /api/health/ отвечает 200; отдельный guarded helper восстановил секрет только существующего локального SSH fixture, без смены пароля. Backend9000 не перезапускался.

Учётная запись viewer сохранена, тестовое членство удалено. Переработка: список с текущим проектом первым, создание и команда отдельными экранами с «К проектам»; динамические вкладки удалены. Роли объяснены; смена роли подтверждается; повторное добавление уже имеющегося участника не перезаписывает его роль. Владелец неизменяем; после self-demotion управление исчезает сразу. Роли проекта управляют членством/созданием объектов; права на существующие ресурсы назначаются отдельно. Авторизация backend не изменялась. Ручной пустой проект `QA UX Projects 1788337703552` оставлен только в QA для следующей проверки смены контекста; исходный активный проект восстановлен.

### 04 — Мой рабочий стол

Проверены каждый checkbox, перенос каждого виджета между колонками, обе стрелки перестановки и их недоступные крайние позиции, пустая колонка, сохранение, повторное открытие, сброс к исходной схеме, отмена локальных правок, обе ветки подтверждения ухода и смены проекта. Сохранение всех скрытых виджетов проверено на живой QA-базе: обзор оставляет сводку и ссылку «Настроить обзор»; переход обратно и восстановление defaults выполнены. Настройки QAadmin и активный проект восстановлены.

Убраны повторяющиеся названия карточек; checkbox теперь одновременно обозначает виджет, под ним краткая польза. Заголовок согласован с меню аккаунта. «Отменить изменения» возвращает сохранённую схему, «Исходное расположение» возвращает defaults; неработающие save/reset отключены. Перестановка и колонки остаются видимыми: это основная задача данной отдельной страницы персональных настроек. Tabs, context menu, search/filter/pagination здесь не нужны и отсутствуют.

Воспроизведена и исправлена потеря черновика при смене проекта: project activation/creation теперь запрашивают подтверждение только при несохранённых изменениях. Отмена сохраняет форму, явное подтверждение продолжает операцию. Ошибки и pending не показывают ложный успех. Hook сохраняет защиту до фактического завершения операции.

`ux-workspace.spec.ts` + существующий personal-layout regression: PASS 4/4 (47 с). Проверены реальные записи с сохранением сторонних JSON-параметров, создание/смена проекта, guards, mobile/axe/overflow; test-only задержки/503 для чтения и записи с сохранением черновика и retry. Все временные аккаунты удалены. Scoped ESLint, typecheck и 3 hook tests — PASS. Лог `frontend/artifacts/ux-workspace-e2e.log`. Полномочия отдельной роли для этой персональной страницы backend не требует; доступ проверяется аутентификацией, запись принадлежит текущему пользователю.

Дополнительная source-проверка выявила и закрыла три сценария: новый ответ фонового запроса обновляет чистый редактор; ошибка обновления при наличии cache показывает banner и сохраняет dirty draft; уже начатое сохранение нельзя ошибочно «отменить» сменой проекта или уходом. Route ждёт ответа записи, project action возвращает понятное сообщение без POST. Повторная source-проверка подтверждает исправления; отдельные browser regressions выполняются перед закрытием страницы.

### 05 — Серверы: текущий десктопный проход

Список и форма: проверены в браузере на 8090/9001 после изменений. Удалены четыре сводных счётчика, повторная ссылка «Открыть», колонка владельца для каждой строки, пустая подпись ОС `unknown`, пагинация единственной страницы и статус «в сети», который backend вычислял из давности подключения, а не из живой проверки. Главный сценарий — найти сервер и открыть терминал — доступен из строки; название открывает карточку. Фильтр группы показывается, когда есть выбор, и отличается от настоящего пустого списка. При неудачном обновлении ранее загруженные серверы остаются доступны.

Backend bootstrap передаёт независимое право `can_connect_terminal`; подключение скрыто при его отсутствии, guard и backend-права сохранены. Дата последнего подключения теперь учитывает реальные `ServerConnection`, а не только ручную проверку SSH. Узкий regression-тест владельца, чтения без терминала, выдачи/отзыва права и даты сеанса: `tests/test_servers_bootstrap_terminal_capability.py` PASS. Реальный browser → SSH fixture → `pwd` вернул `/home/qa`; после возврата и обновления дата появилась в таблице. Отдельный полный UX-проход терминала этим не заменяется.

Browser contract fixtures (только подмена ответа в текущей вкладке, без записей в БД): 18 серверов, две страницы и disabled на последней, все сортировки, поиск/очистка, группа без серверов/сброс, настоящий пустой список, холодная ошибка и восстановление, ошибка обновления с сохранёнными строками, отсутствие кнопки терминала при ограниченном праве. Подмены Fetch и Network сняты, реальный список восстановлен.

Форма: required-поля, неверный порт, JSON-массив вместо объекта сети, sudo без пароля, переключение видов SSH-аутентификации, группа, теги, заметки и AI-контекст. Добавлено подтверждение потери черновика при закрытии/отмене, disabled во время отправки и защита от Escape. Проверены сохранение полей после 503, реальный повторный submit, отмена подтверждения, явный сброс и чистое повторное открытие. Отправляются только секреты выбранного способа входа/sudo. В QA создан сервер `QA UX server 20260902`, id **12**, локальный 127.0.0.1:22391, группа QA environment. Он оставлен для следующих проверок редактирования/доступа/удаления; основной fixture id 1 сохранён.

Статика текущих изменений: TypeScript PASS; ESLint затронутых исходников PASS. Остальные страницы frontend и общая сборка не прогонялись. Карточка, файлы, терминал, AI-чат и остальные активные страницы ещё не приняты. В терминале замечено подтверждение ухода даже после отключения SSH и текст «Канал подключён» при отключённом SSH — разобрать в его проходе.

### 05а — Группы серверов

Десктопный проход на 8090/9001: список, создание/редактирование группы, серверы, доступ, правила AI и массовые изменения. Название группы само открывает её; отдельная кнопка «Открыть» удалена. Основные вкладки — «Серверы» и «Доступ», правила AI и операции для всей группы находятся в «Ещё». «Избранное» и «Подписка» удалены из UI и frontend API: эти записи не использовались интерфейсом. Переменные окружения находятся в раскрываемой секции правил. Пагинация единственной страницы скрыта; даты добавления участников убраны из основной таблицы.

Создание сервера доступно непосредственно из группы и подставляет её в общую форму. Проверены пустая группа, предвыбранная группа в форме, поиск/очистка групп, сортировки, выбор/снятие выбора серверов и реальный перенос только QA-сервера id 12. Формы блокируются на время записи. У создания/редактирования группы есть required/maxLength/проверка повторяющегося имени, отмена черновика и понятная ошибка. Held POST → 503 → повторная отправка проверены при создании группы и сохранении правил.

Участники: форма появляется по кнопке, добавление отделено от изменения роли. Проверены фактическое добавление QAviewer, роли viewer → admin → member, подтверждения изменения/отзыва прав, запрет изменения владельца, повторного добавления и сохранения неизменённой роли; неизвестный логин возвращает ошибку с сохранением ввода. Отзыв подтверждён повторным чтением списка. Под реальным QAviewer вкладка доступа и массовые операции отсутствуют, правила только для чтения, переменные скрыты.
