# Минимальная структура WebTerm

Дата: 2026-09-02. Текущий этап — внедрить сокращённую навигацию перед продолжением постраничной переработки.

Статус: сокращённая десктопная навигация проверена в браузере на frontend 8090 / QA backend 9001. Проверены пять основных разделов, все пункты локальной навигации и дополнительных меню, прямые legacy redirects, 404, смена проекта, тема, выход/вход и скрытие недоступных разделов у реального QA viewer. Самостоятельная UX-приёмка содержимого страниц ещё впереди.

Последние уточнения пользователя: мобильная версия исключена из объёма; глобальный поиск и Ctrl+K удалены. Приоритет — сначала довести «Серверы», затем «AI-чат». Поиск внутри рабочих списков разбирается вместе с соответствующей страницей.

## Основное меню

Пять пунктов: **Серверы · AI-чат · Автоматизация · Агенты · Настройки**. Пункт показывается только при наличии доступной пользователю функции. Не добавлять обзорные страницы между пунктом меню и рабочим инструментом.

| Пункт | Основная задача | Что открывается сразу | Что находится глубже |
|---|---|---|---|
| Серверы | Найти сервер и выполнить работу | Список серверов с поиском и подключением | Терминал, файлы, доступ, сведения и знания конкретного сервера; группы рядом со списком |
| AI-чат | Получить помощь или выполнить задачу с AI | Чат и история диалогов | Контекст сервера выбирается в чате; провайдеры, подключения и модели — в настройках AI |
| Автоматизация | Создать, запустить и проверить сценарий | Playbooks / Pipelines / История запусков | Сейчас черновики, расписания и профили AI-узлов в «Ещё»; контекстное объединение черновиков/расписаний с pipeline — при разборе этой страницы |
| Агенты | Создать и контролировать автономную задачу | Список агентов, затем задача и её запуски | Навыки и MARS в «Ещё», без самостоятельных пунктов основного меню |
| Настройки | Один раз настроить продукт и доступ | AI / Доступ / Интеграции | Аудит, журналирование, хранение, корпоративный вход, лимиты и диагностика в «Дополнительно» |

## Исключено пользователем из текущего интерфейса

| Страница | Решение | Старые адреса |
|---|---|---|
| Обзор | Удалить как стартовый и самостоятельный экран | `/` должен открывать серверы; `/dashboard` переводить на серверы |
| Мой рабочий стол | Убрать настройку несуществующего обзора | `/settings/workspace` переводить на серверы; удалить вход из меню аккаунта |
| Мониторинг | Отложить самостоятельный модуль | `/infrastructure/monitoring`, `/monitoring` переводить на серверы; убрать ссылки на него из активных страниц |
| Kubernetes | Отложить весь модуль, включая вложенные экраны | `/infrastructure/kubernetes/*`, `/kubernetes` переводить на серверы; удалить пункты навигации и поиска |
| Активность команды | Убрать отдельный экран | `/governance/activity` переводить на серверы; аудит безопасности остаётся в настройках |

Это сокращение продуктового интерфейса, а не удаление баз данных, API, журналов безопасности или накопленных результатов. Backend-права и аудит сохраняются.

## Объединения без потери функций

1. **Доступ:** пользователи и группы — вкладки одного раздела. Права изменяются в карточках пользователя/группы; отдельная матрица разрешений доступна через «Дополнительно». Промежуточный `AccessOverview` с карточками переходов убирается, вход ведёт сразу к пользователям.
2. **Интеграции:** MCP-инструменты и плагины — внутри настроек. Сохраняются отдельные формы и проверки прав, поскольку это разные сущности.
3. **AI:** существующий `/settings/ai` получает видимый вход. Провайдеры, CLI-подписки и назначение моделей доступны здесь; пулы и редкие параметры скрыты глубже.
4. **Черновики:** остаются сохранёнными рабочими объектами и частью создания pipelines. Убирается отдельный пункт основного меню, а не восстановление, проверка или публикация черновиков.
5. **Расписания:** создание и изменение рядом с pipeline; общий список оставляется для управления несколькими расписаниями.
6. **Память сервера:** вход из карточки выбранного сервера уже существует. Глобальный пункт меню убирается; поиск, обработка и политика памяти сохраняются.
7. **Профили и агенты:** не объединять данные механически. Профили используются AI-узлами pipelines, автономные агенты решают другую задачу. Поэтому вход «Профили AI-узлов» помещён в автоматизацию, а навыки — в раздел агентов. Контекстные ссылки из редакторов проверяются при разборе их страниц.
8. **История:** результаты, ошибки и отмена запусков должны оставаться быстро доступными. Не удалять историю как «лишний журнал» и не смешивать её с аудитом входов/изменений прав.

## Ограничения навигации и доступа

- Главная для обычного входа — `/infrastructure/servers`; если доступ к серверам не предоставлен, показать честное состояние отсутствия прав, не расширять разрешения.
- Настройки открывают первую доступную рабочую вкладку. `settings` само по себе не даёт доступ к административной форме: текущая GeneralSettings требует также `staff`.
- Для `/settings/ai` сохранить проверку `settings` и `can_manage_ai_routing`; не делать личные разрешённые AI-функции недоступными из-за неверной общей проверки роли.
- Разрешения MCP, плагинов, пользователей и аудита проверять отдельно. Сокращение меню не является заменой route/backend guard.
- Глобальный поиск отсутствует. Вложенные инструменты открываются из локальной навигации раздела.
- Глобальные breadcrumbs, логотип, повторный вход, 404 и ошибки маршрута ведут к серверам, без подписи «Открыть обзор».
- Мобильная UX-приёмка исключена по прямому указанию пользователя. Проверяется десктоп.

## Последовательность внедрения и проверки

1. Открыть текущий интерфейс, зафиксировать исходное меню. Внедрить старт с серверов, исключение пяти экранов и пять пунктов основного меню. Проверить вход, меню аккаунта, redirects и права на десктопе.
2. Пройти серверы: список, группы, создание/изменение, основные действия, подробная карточка, терминал и файлы. Отдельно решить перегруженные вкладки по реальным взаимодействиям.
3. Пройти AI-чат и настройки его подключений; сохранить быстрый выбор серверного контекста.
4. Пройти автоматизацию: playbooks, pipelines, запуски, черновики и расписания. Переносить действия в контекст после проверки их существующих workflows.
5. Пройти агентов, профили, навыки и дополнительные инструменты. Проверить все действующие способы запуска и связи с pipelines.
6. Пройти настройки: AI, пользователи/группы/права, интеграции и дополнительные параметры.
7. Повторно сверить все действующие routes и состояния с реестром. Исключённые пользователем модули помечаются как отложенные, а не как проверенные.

Каждая страница сохраняет исходные требования: браузер до/после, все вкладки и controls, основные действия, empty/loading/error/disabled/permission, поиск/фильтры/сортировка/пагинация, подтверждения опасных операций. Подготовка этой структуры не означает завершения frontend или UX-аудита.

## Проверка внедрения навигации

Выполнено в коде:

- Sidebar содержит по одному входу в каждый доступный основной раздел, без прежних групп из десятков ссылок. Настройки закреплены снизу.
- `SectionNavigation` показывает рабочие вкладки активного раздела; редкие инструменты — через «Ещё» / «Дополнительно». «Доступ» содержит пользователей/группы и дополнительную матрицу прав; «Интеграции» объединяют MCP и плагины с независимыми permissions.
- `NavigationLanding` выбирает первую разрешённую страницу для `/settings`, `/settings/integrations` и `/automation`. Учтена роль только с `studio_agents`, чтобы она попадала в профили AI-узлов вместо запрещённых запусков.
- Логотип, `/`, исключённые legacy paths, 404 и route errors направляют к серверам. Убраны пункт рабочего стола и дублирующий вход в настройки из меню аккаунта.
- Память остаётся доступна из конкретного сервера . Подключение к серверу, backend guards, API и данные не менялись.
- Старые UI-тесты удалённых модулей вынесены в `frontend/tests/deferred/*.disabled`. Shell/аккаунт/permissions сохранены в `ux-shell.spec.ts`; успешный login ожидает серверы. Активные smoke/a11y больше не выдают redirects Kubernetes за проверку модуля. Независимые backend ACL assertions сохранены.

Проверено: TypeScript — PASS; ESLint изменённых исходников и активных тестов — PASS; `tests/navigation.test.ts` — PASS 5/5. Исследование кода выявило и исправило landing для профилей без права запуска pipelines.

**Браузерная проверка навигации:** завершена для текущего десктопного состава. Состояния и CRUD каждой рабочей страницы не засчитываются этим проходом. Глобальный поиск удалён вместе с компонентом, стилями и устаревшими сценариями; подтверждено отсутствие кнопки и реакции приложения на Ctrl+K. Проверки поиска, сделанные ранее, больше не являются частью продукта.

Для последующих страниц зафиксировано: SettingsPages хранит несохранённый draft без route blocker, поэтому переход между настройками может его потерять. На странице общих настроек также остаются прежние ссылки на редкие разделы — убрать их дублирование после индивидуального браузерного прохода. Отложенные capabilities в матрице permissions проверить отдельно при разборе «Доступа»; backend значения автоматически не сбрасывать.
