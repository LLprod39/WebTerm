# Список проблем проекта (Project Issues)

## Краткое резюме
В данном документе собраны текущие проблемы проекта: архитектурные нарушения (Bounded Context Leakage, циклические зависимости), уязвимости безопасности (риски shell-инъекций, слабая криптография, утечки секретов), проблемы производительности (блокировка event loop, N+1 запросы к БД) и технический долг. Список сформирован на основе аудита кодовой базы (`PROJECT_AUDIT.md`) и настроек `.importlinter`.

---

## Critical

### 1. Риск Shell-инъекций (Subprocess / Execution Risks)
- **Где найдено:** `core_ui/views/_views_all.py`
- **Что не так:** Использование `asyncio.create_subprocess_exec` с параметрами, которые потенциально передаются от пользователя или из внешнего окружения без должной валидации.
- **Почему это важно:** Злоумышленник может выполнить произвольные команды на сервере, что приведет к полной компрометации системы (RCE).
- **Рекомендация по исправлению:** Использовать строгую валидацию параметров и отказаться от передачи несанитизированного пользовательского ввода в аргументы командной строки.
- **Статус:** open

### 2. Блокировка асинхронного Event Loop
- **Где найдено:** `app/agent_kernel/memory/store.py` (функция `_try_parse_list_literal`)
- **Что не так:** Синхронный парсинг больших строк и JSON через `ast.literal_eval` внутри асинхронных функций.
- **Почему это важно:** Тяжелые синхронные вычисления блокируют весь асинхронный event loop, из-за чего Django Channels перестает отвечать на другие WebSocket-соединения, что ведет к деградации сервиса.
- **Рекомендация по исправлению:** Обернуть ресурсоемкие синхронные вызовы (например, парсинг AST) в `sync_to_async`.
- **Статус:** open

## High

### 3. Ненадежная проверка безопасности команд (safety.py)
- **Где найдено:** `app/tools/safety.py` (функция `is_dangerous_command`)
- **Что не так:** Безопасность оценивается с помощью простых регулярных выражений (например, `\bkill\b`, `\brm -r\b`).
- **Почему это важно:** Злоумышленники легко могут обойти такие проверки через базовую обфускацию shell-команд (например, `k\ill`, `r\m`, использование переменных).
- **Рекомендация по исправлению:** Заменить проверку регулярными выражениями на парсер на основе AST (например, `bashlex`), чтобы точно определять вызываемые бинарники и их аргументы.
- **Статус:** open

### 4. Недостаточное количество итераций хеширования (Weak Iteration Counts)
- **Где найдено:** `servers.encryption.PasswordEncryption`
- **Что не так:** Используется алгоритм PBKDF2HMAC всего с 100,000 итераций.
- **Почему это важно:** Современные стандарты безопасности требуют от 600,000 итераций для PBKDF2-HMAC-SHA256 для защиты от брутфорс-атак на пароли и ключи серверов.
- **Рекомендация по исправлению:** Увеличить количество итераций PBKDF2 минимум до 600,000 или перейти на более современный алгоритм Argon2id.
- **Статус:** open

### 5. Ограничения механизма скрытия секретов (Secret Redaction)
- **Где найдено:** `app/agent_kernel/memory/redaction.py`
- **Что не так:** Попытка скрыть учетные данные (до логирования или передачи AI) опирается на наивные regex-выражения (`password|token=...`).
- **Почему это важно:** Ключи, передаваемые динамически через JSON или не соответствующие явному паттерну, могут легко утечь в логи или сторонние API (например, LLM).
- **Рекомендация по исправлению:** Внедрить сканирование на основе энтропии (entropy scanning) и проверять структуры данных перед сериализацией.
- **Статус:** open

### 6. Неограниченные запросы к БД и N+1 проблема (Performance)
- **Где найдено:** `core_ui/views/_views_all.py` и `servers/views/_views_all.py`
- **Что не так:** В `core_ui` вызывается `User.objects.all().prefetch_related("groups")` без пагинации (загрузка всей таблицы в память). В `servers` выполняются ORM-запросы внутри циклов (`ServerGroupMember.objects.filter(...)`).
- **Почему это важно:** При росте количества данных такие вызовы приводят к чрезмерному потреблению памяти, падению фоновых процессов и длительному времени ответа.
- **Рекомендация по исправлению:** Внедрить лимиты/пагинацию для списочных эндпоинтов и использовать пакетную выборку (bulk fetch) до начала цикла.
- **Статус:** open

## Medium

### 7. Нарушение архитектурных границ (Bounded Context Leakage)
- **Где найдено:** `app/tools/server_tools.py`, `app/tools/ssh_tools.py`
- **Что не так:** Эти файлы из `app` напрямую импортируют Django-модели из `servers` (например, `Server`, `ServerCommandHistory`, `ServerShare`).
- **Почему это важно:** Тесная связность модулей (coupling) усложняет рефакторинг, тестирование и противоречит заданным архитектурным контрактам (правила `.importlinter`).
- **Рекомендация по исправлению:** Перенести специфичную для серверов логику исполнения из `app/tools/` в `servers/tools/`.
- **Статус:** open

### 8. Циклические зависимости и Inline-импорты
- **Где найдено:** `app/agent_kernel/memory/store.py` и `app/tools/server_tools.py`
- **Что не так:** Использование встроенных (inline) импортов внутри методов (`from servers.models import ...`).
- **Почему это важно:** Это признак неправильно распределенной доменной логики и "костыль" для обхода падений из-за циклических импортов. Снижает читаемость и надежность инициализации.
- **Рекомендация по исправлению:** Реорганизовать доменную логику: отвязать абстракции базы данных от доменных интерфейсов (например, через DI или паттерн Repository).
- **Статус:** open

## Low

### 9. Устаревший слой-посредник (Deprecated Shim)
- **Где найдено:** `servers/mcp_tool_runtime.py`
- **Что не так:** Файл действует как прокси-модуль для `studio`.
- **Почему это важно:** Нарушает изоляцию между границами исполнения/AI (`servers`) и слоем оркестрации (`studio`). Усложняет навигацию по коду.
- **Рекомендация по исправлению:** Удалить устаревший модуль-посредник и рефакторить зависимости, используя инъекцию зависимостей (SkillProvider DI) или сигналы.
- **Статус:** open

### 10. Wildcard-импорты в настройках
- **Где найдено:** `web_ui/settings/*.py` (например, `from web_ui.settings.base import *`)
- **Что не так:** Использование импорта со звездочкой `*`.
- **Почему это важно:** Засоряет пространство имен, из-за чего сложно отследить, откуда именно импортируется переменная или где она переопределяется.
- **Рекомендация по исправлению:** Использовать явные импорты требуемых переменных.
- **Статус:** open

### 11. Незавершенная логика (TODO hotspots)
- **Где найдено:** `servers/consumers/ssh_terminal.py` (строки 1616, 2787)
- **Что не так:** Наличие захардкоженных комментариев `TODO: add json_mode=True`.
- **Почему это важно:** Указывает на недоделанный функционал терминала или парсинга, который может вызывать ошибки при работе с JSON.
- **Рекомендация по исправлению:** Реализовать поддержку `json_mode=True` в соответствующих функциях или убрать комментарий, если неактуально.
- **Статус:** open
